# 图片生成模型调用授权规则

> 本项目硬性限制。任何图片生成模型（含 Qwen-Image 全系、wan/万相、Seedream、Gemini/Nano Banana、GPT-Image、FLUX、z-image 等，无论走本仓库脚本、MCP 工具还是网页端）在发起生成前，必须先取得用户授权。未授权不得调用。
>
> 2026-10-29 由用户指令建立。修改本文件等于修改项目红线，需用户明确同意。

## 一、为什么有这个文件

出图按张计费，一次批量任务可能几十上百张，费用会累积。用途不明时还可能生成不该生成的东西（未发布的款式、他人的图、含平台风险元素的画面）。所以每一次出图都要先讲清两件事：**用在哪里**、**大概花多少**，用户点头之后才动手。

授权不是一次性的通行证。不同批次、不同用途、不同模型各问一次。上一批同意了，不代表这一批可以默认继续。

## 二、发起前必须向用户说明的三项

1. **用途**：这批图要做什么、用在哪里（哪个产品、哪个平台、哪套主图或详情页的第几页）。说得出具体落点，不能只写"电商图"。
2. **模型与通道**：本次将调用哪个模型（如 `qwen-image-2.1-pro`），走哪条通道（本仓库 `tools/qwen_image.py`、MCP 图片工具、网页端）。
3. **预计花费**：`张数 × 单价 = 预计花费`。单价必须取当时官方页面的真实数字，不得凭记忆或按经验估。

## 三、单价的取值口径

- 官方入口：阿里云百炼控制台的模型详情页或「费用与成本」账单页，查看该模型当前的按张单价。
- 不同模型、不同分辨率档位、是否含编辑、是否走折扣，单价都不同，不能混用。
- 拿不到确切单价时，向用户说明"单价待确认"，由用户提供或在控制台确认后填入。**不允许猜测一个数字填进去。**
- 本文档不写死价格，价格会随官方调整变化，写死就会误导。

## 四、命令行通道的执行方式

`tools/qwen_image.py` 已内置闸门：缺少下列任一参数直接拒绝调用，不会发出请求。

```bash
python tools/qwen_image.py -p "提示词" -n 4 --size 1024*1536 \
  --authorize "用户在 2026-10-29 14:20 回复：可以，按这个方案出" \
  --purpose "某某产品天猫详情页第 3 页材质特写" \
  --unit-price 0.25
```

| 参数 | 作用 | 填法 |
|---|---|---|
| `--authorize` | 用户同意的凭证 | 用户原话摘录，或带日期的授权说明。不得由模型自行编造 |
| `--purpose` | 这批图的落点 | 具体到产品、平台、页面位置 |
| `--unit-price` | 每张单价（元） | 官方页面当时显示的数值 |

脚本会在调用前把「用途、张数、单价、预计花费、模型、授权原话」打印到终端，并追加写入 `out/authorization.log` 作为审计记录。`out/` 已在 `.gitignore` 中忽略，该日志只留本机，不进版本库、不推送。

## 五、其他通道的执行方式

- **MCP 图片工具**（如 `bailian_image_gen`、`bailian_image_edit`）：同样先在对话里向用户说明用途、模型、预计花费，取得明确回复后再调用。
- **网页端手工出图**：操作者自行出图的，不受本文件约束；但由 Agent 代操作网页端时同样适用本规则。
- **批量任务**：一批里包含多个提示词时，按整批的总张数报花费，不要拆成多次小额授权绕过确认。
- **重试**：因效果不满意重跑同一批，属于新的一次调用，重新报花费。同一批内的参数微调（改一个词重试一张）可以在原授权范围内继续，但要在日志里记清楚。

## 六、禁止事项

1. 禁止在未取得用户同意时调用任何图片生成模型，包括"先跑一张试试效果"。
2. 禁止自行填写 `--authorize`。该字段必须来自用户的真实回复。
3. 禁止编造单价，或用旧价格充当当前价格。
4. 禁止把一批拆成多批，用来规避单次授权的花费说明。
5. 禁止在用户只同意了某一种用途后，把生成的图挪作他用。

## 七、授权记录的最小字段

每次调用至少留：时间、模型、通道、张数、尺寸、单价、预计花费、用途、用户授权原话。脚本自动写入 `out/authorization.log`；手工或 MCP 通道在对话记录里保留上述信息即可。
