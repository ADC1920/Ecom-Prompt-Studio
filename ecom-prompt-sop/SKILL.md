# 电商视觉五工作室

本技能是电商生图提示词 SOP 的**拆解库**，按五个工位组织。工作方式是**先判工位，再定位唯一一个原子，读对应原子执行**。

每条的提示词模板、规则条款、检查清单、占位符已经分开装好，完整内容也在原子里（`source_text`），所以不需要另找外部文档：模板直接投喂，规则用来自查，清单用来验收。

## 五工位总览

| 工位 | 接什么需求 | 产物 | 门禁 | 入口篇目 |
|---|---|---|---|---|
| ① AI 主图台 | 一套主图、单张主图、买家秀、场景图、白底图 | 主图规划表 + 逐张提示词 + 合规检查 | 保留清单逐张复用｜卖点有依据｜首图规范已核对｜有输出边界句 | 见工位一 |
| ② AI 详情页台 | 一套详情页或长图 | 页面规划 + 逐页提示词 | 每页先锁定后设计｜页面主题互不重复｜防模板化自检 | 见工位二 |
| ③ SKU 批量与跨平台台 | 多色/多件套批量、多产品替换、比例转换、图内文字翻译 | SKU 变体规划 + 逐张提示词 + 转换结果 | 变体归属标明｜主体只改数量颜色版式｜转换后主体不裁切｜文字只译不改 | 见工位三 |
| ④ 模特与视频台 | 模特换头换装、多姿势模特图、电商视频生成 | 模特图系列或视频提示词（含时间轴镜头） | 人脸不漂移｜服装与款式一致｜露脸规则遵守｜视频有时间轴无静图描述 | 见工位四 |
| ⑤ 图片反推台 | 输入别人的图或视频，反推成自己的提示词 | 拆解表 + 替换后完整提示词 + 不继承清单 | 品牌名替换｜商品特性不继承｜自有产品锁定复用｜视频必出分镜 | 见工位五 |

五台共用同一套拆解库，混合篇（品类专项、00 号通用篇、多 SKU 篇）同时挂在两个台，**整篇共用、两处指向，不拆分复制**。

## 原子长什么样

每篇一个原子，存在 `references/_atoms/aNN.json`；`references/_atoms/index.json` 是全部原子的索引（编号、一句话任务、工位、槽位、产物、模板与规则数量）。原子字段：

| 字段 | 内容 | 怎么用 |
|---|---|---|
| `templates` | 提示词模板，代码块型与裸段落型都收，带行号 | 直接取 `text` 投喂；多模板时按 `heading` 选 |
| `rules` | 正文里的规则条款（必须/禁止/不得这类），带行号 | 自查用，交付前逐条对 |
| `checklists` | 验收清单、必备板块这类编号条目 | 验收用，可逐条打勾 |
| `placeholders` | 需要替换的占位符清单 | 交付前确认每个都替换了 |
| `steps` | 步骤标题 | 知道这一篇的执行顺序 |
| `source_text` | 完整内容 | 需要上下文、示例与解释时读 |

`references/_index.json` 是篇目级索引（篇号、工位、品类、产物、触发词、槽位）；两个索引都由 `tools/atomize.py` 维护，改完跑 `merge` 与 `check`。

要把某篇的内容组装成结构化提示词（而不是自由发挥）时，按 `references/_prompt-slots.md` 的五槽位规范组织：保真段 → 场景 → 主体 → 细节 → 用途 → 约束；可用 `tools/compose_prompt.py` 组装并跑必填与反 AI 感校验（技能单独安装时不带脚本，按该规范人工过）。

## 使用流程

1. 从用户消息识别三要素：**品类**（服饰/美妆/美食/3C/家具/包包/海产/杯壶/檀木…）、**产物**（主图/详情页/买家秀/SKU 图/模特图/视频）、**动作**（生成/反推/翻新/替换/翻译/批量）。
2. **判工位**（先于篇目定位），按下列优先级自上而下取第一个命中项：
   - **动作是反推/翻新/复刻/拆解/对标** → 工位五（反推台），不看产物；
   - **要批量变体**（多色、多件套、多产品替换、数量增减、比例转换、图内文字翻译） → 工位三；
   - **要真人或视频**（模特换头换装、多姿势模特图、视频生成） → 工位四；
   - **产物是详情页/长图** → 工位二；
   - **其余视觉素材生成** → 工位一。
3. **裸需求第一判据**：请求是「裸主图方案」或「裸详情页方案」——没有任何品类专项命中，不涉及反推/翻新/复刻/SKU 批量/比例转换/图内文字翻译/买家秀/场景图/模特换装/视频，也未点名本库 SOP——则**不进本库**：主图方案转 `ecom-main-image-prompts` 技能，详情页方案转 `ecom-detail-page-prompts` 技能。其余情形继续第 4 步。
4. 在该工位的篇目表定位**唯一最匹配**的原子。裁决顺序：用户点名篇号 > 品类专项 > 通用篇；用户点名篇号（如「02 号 SOP」「爆款反推里的 04」）按篇目名里的篇号前缀匹配（篇号与目录号 01-05 重合时，以用户描述的内容意图为准，拿不准先问）；两篇都可能匹配时按判据列裁决，仍拿不准就先问用户，不要凭感觉挑。
5. 读 `references/_atoms/aNN.json`（篇目表给出编号），取 `templates` 的模板、`rules` 的规则、`checklists` 的验收项；需要上下文与示例时读同一原子的 `source_text`，不必再找外部文档。
6. 严格按原子里的模板与步骤执行，并按该工位的门禁自查；原子里的硬规则（产品外观锁定、信息真实性、不露脸等）不得删减或弱化。
7. 原子未覆盖的边缘品类，选最接近的品类专项或通用篇，并向用户说明选择依据。

## 与既有技能的分工

裸主图/裸详情页的通用方案由 `ecom-main-image-prompts`、`ecom-detail-page-prompts` 承接（第 3 步第一判据）。本技能的价值在**拆解后的模板与细分场景**：品类专项规则、爆款反推、SKU 批量、图翻译、模特与视频等，以及用户点名要完整 SOP 时。

## 工位一：AI 主图台

**输入**：产品图（1 张或多张同产品角度图）、目标平台、品类、主图数量与比例、模特与人脸要求、允许出现的图内文字。

**产物**：主图规划表（每张的职责／比例／背景／是否模特／文字规则／核心信息）+ 逐张完整提示词 + 合规检查。

**门禁**：①产品保留清单在每张提示词里完整复用；②每条卖点按「已确认／有依据／待补证／禁止」分级，只说前两级；③首图符合目标平台规范（白底、占比、文字限制）；④每张以输出边界句收尾。

本台只做**单款单套**；要出多色、多件套、多数量或换比例，走工位三；要真人出镜或视频，走工位四。

### 单品主图（01 通用）

| 用户场景与判据 | 读这篇原子 |
|---|---|
| 国内平台常规主图整套（实拍转白底 → 固定 6+2 张），**未提**模特/人脸/跨境 | `_atoms/a03.json`（02 全品类主图通用 SOP） |
| 主图/轮播图 + **提了**模特/人脸规则/平台合规/跨境平台 | `_atoms/a06.json`（07 全平台品类主图提示词 SOP，可选模特与人脸规则） |
| 同一场景批量出真实手机买家秀 | `_atoms/a07.json`（上传产品批量生成相同场景真实手机买家秀 SOP） |
| 产品场景图，1 个核心场景 + 统一风格 | `_atoms/a08.json`（产品场景图单一核心场景生成 SOP） |
| 主图与详情页要一套连做（含跨境） | `_atoms/a01.json`（00 全平台品类主图详情页通用 SOP，含跨境） |

02 与 07 都匹配「主图」时的裁决：用户提到模特、人脸、平台合规、跨境平台、轮播图，任一命中选 07（`a06`）；全未提且是国内平台常规主图选 02（`a03`）。买家秀虽名为「批量」，属同一产品同场景出图，仍留本台。

## 工位二：AI 详情页台

**输入**：产品图（1 张或多张同产品视角图）、平台、详情页页数、风格、产品参数。

**产物**：页面规划（每页关键词与职责）+ 逐页完整提示词。

**门禁**：①每页先写产品锁定约束，再写设计画面；②相邻页面主题不重复；③防模板化自检——整套关键词与信息模块换个产品也能用，就重写；④每页写清构图、景别、镜头、产品位置、信息布局、文字排版、背景材质、光影，不得只说「放标题」。

| 用户场景 | 读这篇原子 |
|---|---|
| 只要详情页整套提示词（含跨境） | `_atoms/a02.json`（01 全平台品类详情页生成，含跨境电商） |
| 详情页要带五点式卖点模块（每卖点配小标题） | `_atoms/a04.json`（05 带五点式卖点的电商详情页生成 SOP） |
| 详情页 + 模特局部不露脸规则 | `_atoms/a05.json`（06 全平台品类详情页生成提示词 SOP，含模特局部不露脸） |
| 主图与详情页要一套连做（含跨境） | `_atoms/a01.json`（00 全平台品类主图详情页通用 SOP，含跨境） |
| 命中具体品类 | 读工位一「品类专项」表同一原子的详情页模板 |
| 同款多色/多 SKU 的详情页 | `_atoms/a26.json`（多 SKU 产品图以及详情页生成 SOP） |

工位一「品类专项」表的十个原子，本台全部共用：主图模板归工位一，详情页模板归本台。

## 工位三：SKU 批量与跨平台台

**输入**：已定款产品图、SKU 清单（颜色、数量、组合方式）、目标平台与输出比例、需要翻译的文字或目标语言。

**产物**：SKU 变体规划（每个变体的数量／颜色／组合／比例）+ 逐张完整提示词 + 跨平台规格转换结果（比例、尺寸、平台差异）。

**门禁**：①每张图标注所属 SKU 变体，不漏不重；②产品主体与原图一致，只允许改变数量、颜色、组合与版式，不得改款式与结构；③比例转换后主体完整不裁切、不拉伸；④图内文字只翻译不重写，字体层级与位置保持不变；⑤多产品替换时，被替换项与新增项的位置关系写清。

| 用户场景 | 读这篇原子 |
|---|---|
| 标款 SKU 图 → 批量出 3/5/8 件套等不同数量 | `_atoms/a25.json`（同产品不同数量的 SKU 图批量生成） |
| 同款多色/多 SKU 的产品图 | `_atoms/a26.json`（多 SKU 产品图以及详情页生成 SOP） |
| 场景图里替换/新增多个产品 | `_atoms/a27.json`（多产品替换流程，含提示词创作过程） |
| 3:4 主图批量转 1:1 | `_atoms/a28.json`（批量 3:4 主图转 1:1） |
| 电商图内文字批量翻译成目标语言 | `_atoms/a29.json`（批量翻译电商图文字为目标语言） |

多 SKU 原子同时含详情页模板：SKU 变体的产品图归本台，详情页页面策划交工位二读同一个原子。本台属成品批量处理，输入可以是任何台已产出的图。

## 工位四：模特与视频台

**输入**：产品图、模特要求（类型、体型、姿势、是否露脸、脸型参考）、视频时长与镜头数、目标平台与比例。

**产物**：模特图系列（换头／换装／多姿势）或电商视频生成提示词（含时间轴、逐镜头描述、动效）。

**门禁**：①同一套模特图里人脸与身体特征不漂移；②服装与服装款式、颜色、细节跟产品一致，不得换款；③禁止露脸或局部不露脸的要求逐张落实；④视频提示词必须写时间轴与逐镜头动作，不得用静图描述充数；⑤批量姿势图要标明每张的姿势差异点，避免同姿势重复。

| 用户场景 | 读这篇原子 |
|---|---|
| 模特换头/换装、批量不同姿势模特图 | `_atoms/a31.json`（模特换头换装与批量不同姿势模特图） |
| 产品图 → 电商视频生成提示词 | `_atoms/a30.json`（全品类产品电商视频生成 SOP） |

模特出镜但只做单张主图、不涉及换头换装时，走工位一的 07 号主图篇（`a06`）。视频反推（拆解别人的视频）走工位五。

## 工位五：图片反推台

**输入**：对标图（可多张）、对标视频、自家产品图，以及要继承的范围（只继承风格／含版式）。

**产物**：拆解表（是否保留品类／构图／色彩／光影／材质／版式／文字层级／镜头节奏）+ 替换后完整提示词 + 不继承清单。

**门禁**：①品牌名与商标一律替换，不照抄；②商品特性不继承——只继承构图、色彩、光影、版式、节奏这层壳；③自家产品的锁定描述全程复用；④视频反推必须先出分镜或故事板，否则不可执行。

### 静图反推

| 用户场景 | 读这篇原子 |
|---|---|
| 对标爆款的主图 → 反推出自己的主图提示词（先改品牌名） | `_atoms/a10.json`（04 爆品主图反推通用 SOP） |
| 对标爆款的详情页 → 反推出自己的详情页提示词 | `_atoms/a09.json`（03 爆品详情页反推通用 SOP） |
| 对标场景图 → 反推场景提示词并批量生成 | `_atoms/a11.json`（反推对标场景并批量生成） |
| 手里的电商图太土，翻新升级成高级感 | `_atoms/a12.json`（小白图翻新成大师图 SOP） |
| 把自家产品放进对标爆款 SKU 的版式/背景/构图里 | `_atoms/a13.json`（爆款 SKU 复刻替换提示词） |
| 只反推详情页的设计风格/构图/色彩，不继承商品特性 | `_atoms/a14.json`（详情页设计风格构图色彩反推提示词 SOP） |

### 视频反推

| 用户场景 | 读这篇原子 |
|---|---|
| 拆解一段视频 → 可复用的镜头提示词（不带产品） | `_atoms/a32.json`（视频反推 SOP，无需产品） |

## 硬规则

- **忠实模板**：原子里的提示词是调校过的成品，引用时保持规则条款完整，不做「精简版」「合并版」；确需按用户产品定制填充，只替换占位内容，不动规则。原子的 `rules` 与 `checklists` 是这套成品的判据，交付前逐条对。
- **示例值必须替换**：模板里已填死的具体值（目标语言、平台名、品牌名、张数、比例等）一律按用户需求替换后再输出；拿不准某个值是示例还是固定要求，先问用户。原子的 `placeholders` 列了需要替换的占位符，逐个替换完再交付。
- **不过度发挥**：原子没写的平台规则、参数、价格、认证不得编造；原子明确说「不能确认就保守表达」的，照做。
- **一次只路由一篇**：不要同时读多个同类原子拼接输出；用户要主图+详情页两样时，可各读对应模板但分开交付。
- 原子内互相引用的编号（如「见第 X 步」）以该原子自身为准。
- **反 AI 感**：提示词不堆 8k / masterpiece / hyperrealistic / 极致 / 完美 这类空洞词，改用材质、光位、镜头与物理关系描述；规避过度光滑、塑料感高光、完美对称、悬浮无投影、不可能反射等 AI 痕迹。定稿后可用 `tools/slop_check.py` 自查（单独安装技能目录时不带脚本，按本段清单人工过）。
- **生成后机检**：出图后按目标平台跑 `tools/check_image.py`（白底纯度 / 主体占比 / 比例 / 分辨率 / 文件大小 / OCR 文字），机检不过的图不交付、不上架。机检只覆盖可机检的子集，模特造型、AI 标注义务与货不对板仍需人工核对。
