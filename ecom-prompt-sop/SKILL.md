# 电商视觉五工作室

本技能是 34 篇电商生图提示词 SOP 的原文库，按五个工位组织。工作方式是**先判工位，再定位唯一一篇，读原文执行**。所有提示词和步骤都在 `references/` 原文里，本文件只做分台与路由，不复制提示词内容。

## 五工位总览

| 工位 | 接什么需求 | 产物 | 门禁 | 入口篇目 |
|---|---|---|---|---|
| ① AI 主图台 | 一套主图、单张主图、买家秀、场景图、白底图 | 主图规划表 + 逐张提示词 + 合规检查 | 保留清单逐张复用｜卖点有依据｜首图规范已核对｜有输出边界句 | 见工位一 |
| ② AI 详情页台 | 一套详情页或长图 | 页面规划 + 逐页提示词 | 每页先锁定后设计｜页面主题互不重复｜防模板化自检 | 见工位二 |
| ③ SKU 批量与跨平台台 | 多色/多件套批量、多产品替换、比例转换、图内文字翻译 | SKU 变体规划 + 逐张提示词 + 转换结果 | 变体归属标明｜主体只改数量颜色版式｜转换后主体不裁切｜文字只译不改 | 见工位三 |
| ④ 模特与视频台 | 模特换头换装、多姿势模特图、电商视频生成 | 模特图系列或视频提示词（含时间轴镜头） | 人脸不漂移｜服装与款式一致｜露脸规则遵守｜视频有时间轴无静图描述 | 见工位四 |
| ⑤ 图片反推台 | 输入别人的图或视频，反推成自己的提示词 | 拆解表 + 替换后完整提示词 + 不继承清单 | 品牌名替换｜商品特性不继承｜自有产品锁定复用｜视频必出分镜 | 见工位五 |

五台共用同一套原库，混合篇（品类专项、00 号通用篇、多 SKU 篇）同时挂在两个台，**整篇共用、两处指向，不拆分复制**。

## 使用流程

1. 从用户消息识别三要素：**品类**（服饰/美妆/美食/3C/家具/包包/海产/杯壶/檀木…）、**产物**（主图/详情页/买家秀/SKU 图/模特图/视频）、**动作**（生成/反推/翻新/替换/翻译/批量）。
2. **判工位**（先于篇目定位），按下列优先级自上而下取第一个命中项：
   - **动作是反推/翻新/复刻/拆解/对标** → 工位五（反推台），不看产物；
   - **要批量变体**（多色、多件套、多产品替换、数量增减、比例转换、图内文字翻译） → 工位三；
   - **要真人或视频**（模特换头换装、多姿势模特图、视频生成） → 工位四；
   - **产物是详情页/长图** → 工位二；
   - **其余视觉素材生成** → 工位一。
3. **裸需求第一判据**：请求是「裸主图方案」或「裸详情页方案」——没有任何品类专项命中，不涉及反推/翻新/复刻/SKU 批量/比例转换/图内文字翻译/买家秀/场景图/模特换装/视频，也未点名本库 SOP——则**不进原库**：主图方案转 `ecom-main-image-prompts` 技能，详情页方案转 `ecom-detail-page-prompts` 技能。其余情形继续第 4 步。
4. 在该工位的篇目表定位**唯一最匹配**的 SOP 文档。裁决顺序：用户点名篇号 > 品类专项 > 通用篇；用户点名篇号（如「02 号 SOP」「爆款反推里的 04」）按路由表文件名前缀匹配（篇号与目录号 01-05 重合时，以用户描述的内容意图为准，拿不准先问）；两篇都可能匹配时按判据列裁决，仍拿不准就先问用户，不要凭感觉挑。
5. 用 Read 读取该文档全文（路径相对本技能目录，篇目表已给出完整路径）。
6. 严格按文档的步骤和提示词执行，并按该工位的门禁自查；文档里的硬规则（产品外观锁定、信息真实性、不露脸等）不得删减或弱化。
7. 文档未覆盖的边缘品类，选最接近的品类专项或通用篇，并向用户说明选择依据。

## 与既有技能的分工

裸主图/裸详情页的通用方案由 `ecom-main-image-prompts`、`ecom-detail-page-prompts` 承接（第 3 步第一判据）。本技能的价值在**原文与细分场景**：品类专项规则、爆款反推、SKU 批量、图翻译、模特与视频等，以及用户点名要 SOP 原文时。

## 工位一：AI 主图台

**输入**：产品图（1 张或多张同产品角度图）、目标平台、品类、主图数量与比例、模特与人脸要求、允许出现的图内文字。

**产物**：主图规划表（每张的职责／比例／背景／是否模特／文字规则／核心信息）+ 逐张完整提示词 + 合规检查。

**门禁**：①产品保留清单在每张提示词里完整复用；②每条卖点按「已确认／有依据／待补证／禁止」分级，只说前两级；③首图符合目标平台规范（白底、占比、文字限制）；④每张以输出边界句收尾。

本台只做**单款单套**；要出多色、多件套、多数量或换比例，走工位三；要真人出镜或视频，走工位四。

## 工位二：AI 详情页台

**输入**：产品图（1 张或多张同产品视角图）、平台、详情页页数、风格、产品参数。

**产物**：页面规划（每页关键词与职责）+ 逐页完整提示词。

**门禁**：①每页先写产品锁定约束，再写设计画面；②相邻页面主题不重复；③防模板化自检——整套关键词与信息模块换个产品也能用，就重写；④每页写清构图、景别、镜头、产品位置、信息布局、文字排版、背景材质、光影，不得只说「放标题」。

|---|---|

| 详情页要带五点式卖点模块（每卖点配小标题） | `references/01_通用主图详情页/05 带五点式卖点的电商详情页生成 SOP.md` |
| 详情页 + 模特局部不露脸规则 | `references/01_通用主图详情页/06 全平台品类详情页生成提示词 SOP（含模特局部不露脸）.md` |
| 主图与详情页要一套连做（含跨境） | `references/01_通用主图详情页/00 全平台品类主图详情页通用 SOP（含跨境）.md` |

## 工位三：SKU 批量与跨平台台

**输入**：已定款产品图、SKU 清单（颜色、数量、组合方式）、目标平台与输出比例、需要翻译的文字或目标语言。

**产物**：SKU 变体规划（每个变体的数量／颜色／组合／比例）+ 逐张完整提示词 + 跨平台规格转换结果（比例、尺寸、平台差异）。

**门禁**：①每张图标注所属 SKU 变体，不漏不重；②产品主体与原图一致，只允许改变数量、颜色、组合与版式，不得改款式与结构；③比例转换后主体完整不裁切、不拉伸；④图内文字只翻译不重写，字体层级与位置保持不变；⑤多产品替换时，被替换项与新增项的位置关系写清。

| 同款多色/多 SKU 的产品图 | `references/04_SKU批量与跨平台处理/多SKU产品图以及详情页生成SOP.md` |
| 场景图里替换/新增多个产品 | `references/04_SKU批量与跨平台处理/多产品替换流程（含提示词创作过程）.md` |

| 电商图内文字批量翻译成目标语言 | `references/04_SKU批量与跨平台处理/批量翻译电商图文字为目标语言.md` |

## 工位四：模特与视频台

**输入**：产品图、模特要求（类型、体型、姿势、是否露脸、脸型参考）、视频时长与镜头数、目标平台与比例。

**产物**：模特图系列（换头／换装／多姿势）或电商视频生成提示词（含时间轴、逐镜头描述、动效）。

**门禁**：①同一套模特图里人脸与身体特征不漂移；②服装与服装款式、颜色、细节跟产品一致，不得换款；③禁止露脸或局部不露脸的要求逐张落实；④视频提示词必须写时间轴与逐镜头动作，不得用静图描述充数；⑤批量姿势图要标明每张的姿势差异点，避免同姿势重复。

| 用户场景 | 读这篇 |
|---|---|
| 模特换头/换装、批量不同姿势模特图 | `references/05_模特与视频生成/模特换头换装&批量不同姿势模特图教程.md` |
| 产品图 → 电商视频生成提示词 | `references/05_模特与视频生成/全品类产品电商视频生成sop.md` |

## 工位五：图片反推台

**输入**：对标图（可多张）、对标视频、自家产品图，以及要继承的范围（只继承风格／含版式）。

**产物**：拆解表（是否保留品类／构图／色彩／光影／材质／版式／文字层级／镜头节奏）+ 替换后完整提示词 + 不继承清单。

**门禁**：①品牌名与商标一律替换，不照抄；②商品特性不继承——只继承构图、色彩、光影、版式、节奏这层壳；③自家产品的锁定描述全程复用；④视频反推必须先出分镜或故事板，否则不可执行。

## 改稿回流

改一处，下游按表重做。越靠前的改动，波及越大。

| 改了什么 | 回哪台 | 下游要重做什么 |
|---|---|---|
| 反推拆解表定稿 | 主图台 / 详情页台 | 按拆解表出整套，不回头改拆解 |
| 主图风格锁变更 | 详情页台 / SKU 台 | 详情页套图风格锁同步，SKU 变体图重出 |
| 产品外观描述修正 | 五台全部 | 保留清单与锁定描述重写，所有提示词重出 |
| 目标平台变更 | 主图台 / SKU 台 | 首图规范、比例、AI 标注义务重判，变体比例重转 |
| 卖点证据变更 | 五台全部 | 证据账本重分级，涉及该卖点的图与页重出 |
| 详情页页数增减 | 详情页台 | 仅调整受影响页，首尾呼应重新检查 |
| SKU 清单增减（颜色/数量） | SKU 台 | 变体规划重排，新增与删除项的图重出 |
| 模特或人脸规则变更 | 模特与视频台 / 主图台 | 模特图系列重出，主图里含模特的张次重判 |

## 硬规则

- **忠实原文**：SOP 里的提示词是调校过的成品，引用时保持规则条款完整，不做「精简版」「合并版」；确需按用户产品定制填充，只替换占位内容，不动规则。
- **示例值必须替换**：SOP 示例里已填死的具体值（目标语言、平台名、品牌名、张数、比例等）一律按用户需求替换后再输出；拿不准某个值是示例还是固定要求，先问用户。
- **不过度发挥**：文档没写的平台规则、参数、价格、认证不得编造；文档明确说「不能确认就保守表达」的，照做。
- **一次只路由一篇**：不要同时读多篇同类 SOP 拼接输出；用户要主图+详情页两样时，可各读对应篇但分开交付。
- 文档内互相引用的编号（如「见第 X 步」）以被读文档自身为准。
